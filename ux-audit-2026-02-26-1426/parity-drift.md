# V1 → V2 parity drift report

Range: main's changes `28af00f..5b60e22^2` (145 commits), compared with V2 views on HEAD `5b60e22` (merge of main into the remake).

Method: for each V2 view routed on HEAD, I diffed its V1 counterpart (and the components and composables it imports) between `28af00f` and `5b60e22^2`. I then grepped HEAD's V2 code for each change. Claims marked **BROKEN** were checked against the API source (`/Volumes/Vault/repos/ccf/api`, read-only).

Classification:

- **PRESENT**: the change is in the V2 view.
- **MISSING**: the change is not in the V2 view.
- **PARTIAL**: the change is incomplete in V2, or only reachable through an embedded V1 component, or could not be fully verified.
- **N/A**: intentionally dropped, or not relevant to the V2 design.
- **BROKEN**: V2 calls the API in a way that fails or silently loses data.

Evidence paths are on HEAD unless they are prefixed with `main:` (meaning `5b60e22^2:`). Several V1 partials and components are byte-identical on HEAD and main. Their paths are given without a prefix.

## Endpoint and type drift

- `src/types`, `src/oscal`, `src/stores` and shared `src/composables` on HEAD are identical to main; HEAD only adds V2 files. There is no type-level drift.
- **V2 still sends to an endpoint it shouldn't:** B1 (a requirement-level POST that doesn't exist) and B2 (shared-responsibility subtrees sent to a PUT that ignores them).
- **V2 omits a field the endpoint needs:** B3 (`sspId` on filter PUT/POST).
- **V2 calls endpoints that are fine:**
  - `GET /api/filters?controlId=` is supported.
  - `GET /api/oscal/profiles/:id` is a standard endpoint.
  - The old `PUT /system-security-plans/:id/profile` is no longer called by any V2 view. The dead `attachProfile` store method is the same on main.
- **Main endpoints V2 never calls:**
  - `/system-security-plans/:id/risks?limit=100` (risk badges).
  - `suggest-components`, `apply-suggestions` and `dashboard-suggestions`.
  - `/leveraged-controls` at page level.
  - The dedicated `/export`, `/inherited` and `/satisfied` sub-resources.
  - `/api/oscal/component-definitions` (component templates).
- **Unverified:**
  - Whether the API accepts the empty `implementation-status.state` that V2 sends (Controls #5).
  - Whether it accepts the empty `importProfile.href` in the V2 SSP create payload (`createSystemSecurityPlanDefaults.ts:77-79`).
